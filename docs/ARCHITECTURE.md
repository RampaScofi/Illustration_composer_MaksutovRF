# Архитектура Illustration_composer (VectorMuse)

Документ фиксирует структуру этапа 4 и направления развития.
Изменения публичных типов типовых сущностей (`src/types/`) оформляются
как отдельное решение с перечнем последствий.

## 1. Инварианты проекта

1. **Только исходные объекты.** Итоговая композиция состоит исключительно
   из SVG-компонентов подготовленной библиотеки. Генерация и перерисовка
   графических объектов запрещены; AI допустим только как подборщик
   существующих компонентов по метафоре.
2. **Вектор до конца.** Размещение, трансформации и перекраска выполняются
   атрибутами SVG (`transform`, замена литералов цветов). Геометрия путей
   не изменяется, растрирование не выполняется. Экспорт — самостоятельный
   SVG-документ.
3. **Каталог отделён от логики.** Библиотека — статические файлы и манифест;
   код приложения их только читает. Замена библиотеки не требует правки логики.
4. **MVP без аккаунтов.** Регистрация, БД, облачное хранение и совместное
   редактирование отсутствуют; состояние композиции живёт в клиенте.
5. **Ключ ИИ не покидает сервер приложения в сторону браузера.** Браузер
   отправляет запрос только на `POST /api/ai/compose`; маршрут обращается
   к провайдеру. Ключ хранится в `localStorage` и не попадает в логи,
   ответы и тексты ошибок. Ограничения хранения описаны в README.

## 2. Слои и ответственность модулей

```
src/types/            доменные типы, без зависимостей от слоёв
  geometry.ts         точки, размеры, viewBox
  library.ts          компонент библиотеки, манифест, размеры L/S, роли
  palette.ts          схема, слоты цвета, отображение цветов
  composition.ts      экземпляр на холсте, композиция, форматы

src/lib/              чистая логика: без React, без DOM*; сетевые вызовы — только client.ts (к собственному маршруту)
  svg/viewBox.ts      парсинг viewBox, вписывание с сохранением пропорций
  svg/sanitize.ts     проверка/очистка импортируемого SVG (script, on*, внешние ссылки)
  palette/mapping.ts  normalizeHex, buildColorMapping, repaintSvg, extractColors
  palette/schemes.ts  три схемы, слоты, фоны и декоративные подложки Figma
  palette/apply.ts    единая перекраска для холста и экспорта
  metadata/validate.ts строгая валидация манифеста и схем (дубли id, битый viewBox)
  composition/canvas.ts форматы холста, contain-масштаб, адаптация объектов
  composition/autoLayout.ts безопасные отступы и авто-раскладка сцены
  composition/exportSvg.ts сериализация сцены в самостоятельный SVG
  semantic/normalize.ts нормализация описания (регистр, ё, стоп-слова, стемминг)
  semantic/associations.ts словарь ассоциаций: 10 концептов
  semantic/matcher.ts  ранжирование компонентов и выбор плана композиции
  library/librarySource.ts точка подключения библиотеки, честный статус импорта
  composition/projects.ts вкладки проектов: создание, переименование, закрытие
  ai/types.ts          настройки ИИ, запрос и проверенный вариант
  ai/contract.ts       системный промпт, сообщение пользователя, каталог для модели
  ai/providers.ts      провайдеры (OpenAI, Anthropic, свой endpoint), формирование запроса
  ai/validate.ts       проверка ответа модели: id, роли, категории, размер
  ai/request.ts        разбор тела запроса маршрута (лимиты длины и числа вариантов)
  ai/settings.ts       хранение настроек в localStorage, причина блокировки ИИ
  ai/client.ts         запрос из браузера к /api/ai/compose
  ai/variants.ts       вариант модели → элементы автолейаута

src/app/api/ai/compose/route.ts  серверный маршрут: вызов провайдера, таймаут 30 с, лимит тела 512 KB

src/components/       презентационные React-компоненты
  app/                ProjectShell (библиотека и ИИ-настройки общие, проекты раздельно),
                      ProjectTabs, AppHeader, Workbench (состояние сцены и действий одного проекта)
  ai/                 AiSettingsPanel — ключ, провайдер, модель
  library/            LibraryPanel — список компонентов по размерному набору
  canvas/             WorkSurface — SVG-холст, contain-масштаб, манипуляции
  settings/           SettingsPanel — формат, набор, схема, фон
  compose/            ComposePanel — описание, примеры, запуск подбора
  panel/              PanelFrame, EmptyState — общие каркасы панелей

src/app/              маршрутизация Next.js: layout, page, globals.css
tests/                модульные тесты чистых модулей (node:test)
public/assets/        выгруженная библиотека (этап 2): иллюстрации, манифест, палитры
```

\* `sanitize.ts` работает со строкой и одинаково выполняется на сервере и в браузере.

## 3. Поток данных

```
Figma-исходник (только чтение)
        │  export-скрипт этапа 2 (FIGMA_TOKEN, REST API /v1/images?format=svg)
        ▼
public/assets/illustrations/{L,S}/*.svg  +  manifest.json  +  palettes/schemes.json
        │  загрузка + validateLibraryManifest / validateColorScheme
        ▼
LibrarySnapshot (components, schemes, status)
        │  LibraryPanel (ручной выбор)  либо  ComposePanel (описание)
        ▼
normalizeText → matchComponents → selectCompositionPlan
        │  ранжирование по названию, синонимам, тегам и словарю ассоциаций
        ▼
Composition.elements: CompositionElement[]  (ссылка на componentId + трансформация)
        │  buildAutoLayout — главный, вспомогательные и фоновый объекты, отступы, слои
        │  перемещение/поворот/дублирование/удаление/порядок слоёв — только атрибуты
        │  repaintContents(component, scheme, mode) — перекраска по выбранной схеме
        ▼
WorkSurface (рендер <svg> в DOM)  →  exportSvg: заливка + подложка + перекраска + сериализация
```

Локальный подбор не вызывает внешних API. ИИ-компоновка (если включена и
настроена) выполняется так: клиент собирает каталог `buildAiCatalog`
(только объекты выбранного размера, роли primary и background, без backdrop)
и отправляет его с описанием на `/api/ai/compose`; сервер вызывает провайдера
с системным промптом из `contract.ts`; ответ проходит `validateAiResponse`
(неизвестные id, неверные роли, повтор категории отбрасываются). Из проверенного
варианта `buildVariantLayout` строит геометрию. При сбое или пустом результате
используется локальный подбор с уведомлением. Новые графические объекты не
создаются. План композиции выбирается из объектов библиотеки; при отсутствии
совпадений интерфейс честно сообщает об этом.

Фон холста — двухслойный: базовая заливка цвета схемы и декоративная
подложка из Figma (`role: backdrop`, отдельные SVG в размерах L/S).
Подложка вписывается как `cover` (`preserveAspectRatio="xMidYMid slice"`),
поэтому один и тот же файл подходит для любого формата холста; при
экспорте она становится вложенным `<svg>` под объектами.

## 4. Ключевые решения

| Решение | Обоснование |
| --- | --- |
| Next.js App Router + React + TS + Tailwind | требование стека; типы на границах слоёв |
| SVG в DOM вместо canvas | инвариант векторности; редактируемость результата |
| Трансформации через атрибуты `<g>` | объекты исходника не изменяются |
| Перекраска заменой hex-литералов | аналог поведения плагина перекраски в Figma |
| Манифест библиотеки вместо сканирования папок | метаданные (tags, роль, размер) нельзя вывести из файла надёжно |
| node:test вместо Jest/Vitest | нулевые зависимости, нативный запуск TS в Node ≥ 22.18 |
| Валидация манифеста обязателна | битый viewBox/путь делает корректную сборку невозможной |

## 5. Тестуемость

Чистые модули не имеют побочных эффектов, покрыты тестами:
viewBox, sanitize, palette, схемы и перекраска, metadata, форматы холста,
авто-раскладка, семантика и интеграция с библиотекой. Компоненты интерфейса
тонкие; состояние сцены живёт в `Workbench`, вычисления — в `src/lib`.

## 6. Известные ограничения этапа 4

- Локальный подбор словарный: понимает термины из названий, синонимов, тегов
  и 10 концептов словаря ассоциаций. Опечатки не исправляются.
- ИИ-компоновка не проверялась на реальных ключах и провайдерах в этом этапе.
  Актуальность идентификаторов моделей не подтверждена: модель вводится
  пользователем вручную.
- Ключ ИИ хранится в `localStorage` без шифрования (см. README).
- Библиотека содержит 12 уникальных иллюстраций, поэтому композиция состоит
  из 2–4 объектов; новые объекты не генерируются.
- Белые контуры исходных SVG не перекрашиваются и остаются частью объектов.
